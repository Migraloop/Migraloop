# Release Quality Gate on every PR, with Lab↔CI capability twins

We keep ADR-0011’s four Release Quality Gate slices (correctness, Oracle→Mongo contract, performance/load with regression thresholds, basic fault) and ADR-0025’s rule that Lab Scenarios stay manual on real engines. We decide that the full gate runs on **every PR/push** (not only at release time), and that a shipped first-class capability is incomplete until it has both a Lab Scenario **and** non-ignored **contract-path CI coverage** of the same behavior (capability → Lab Scenario → CI twin). CI twins use the in-process contract/stub harness plus CI-provisioned Platform Store/Target services—not Lab Fixture, not live Oracle, and not “run the Lab catalog in CI.” Performance is a separate contract-path microbench with a committed baseline and allowed regression percentage; Lab `bulk-load` remains manual. We rejected Lab-in-CI (conflicts with ADR-0025 and is too heavy/flaky for every PR) and CI-only completeness (leaves real-engine gaps the Lab exists to catch).

CI shape: keep **Handbook guard** as its own workflow; add a Release Quality Gate workflow with three parallel jobs—**rqg-unit** (crate tests without Postgres/Mongo), **rqg-integration** (non-ignored `migraloop-app` tests; correctness/contract/fault and capability CI twins), and **rqg-perf** (microbench). Do not shard integration further by capability until wall-clock or flake cost justifies it. Implementation may land in phases (wire existing tests → close twin gaps → add perf → docs/templates), but the end state is the full gate green on every PR.
