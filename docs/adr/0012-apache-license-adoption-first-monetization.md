# Apache-2.0 core, adoption first; services now, open core later

We choose **Apache-2.0** for the open core to maximize adoption. Near-term monetization is support, consulting, and customer-environment delivery—not multi-tenant SaaS (this tool must sit next to customer source/target DBs). Enterprise/open-core paid modules are a planned later path; v1 must not paint the architecture into a corner where nothing valuable can be commercialized, but v1 itself optimizes for adoption over enclosure.
