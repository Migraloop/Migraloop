# Modular monorepo with a single v1 binary, seams for later paid modules

The codebase is one repository split into modules aligned with the domain (types, capture, platform-store, transform, delivery, runtime, cli, app). `types` is a leaf crate for shared TLS settings, Managed-field mapping, and secret-reference resolution on the apply path. `capture` exposes the Source System engine interface (`SourceEngine` / `IncrementalCaptureSession`) with Oracle LogMiner contract + OCI adapters (and an in-memory fake for tests). `delivery` exposes the Target System engine interface (`TargetEngine`) with MongoDB as the v1 adapter (and an in-memory fake for tests). `runtime` owns Deployment apply, table-level Initial Load, Direct/Transform Pipeline Delivery, Incremental Sync orchestration (including continuous supervise), Transform Affect → Derived → Delivery, Pipeline lifecycle (pause / resume / remove / change-via-apply), Source Alignment Check, Drift Check, and status inventory reads—depending on Source/Target engine interfaces rather than Oracle/Mongo concrete types; the CLI is a thin Operator adapter over that interface. `transform` owns the single Affect Analysis interface (including Maintenance State protocol) and Derived output schema inference. v1 still ships as one app binary plus Platform Store. This keeps adoption simple while preserving clear boundaries so future open-core/enterprise modules can be licensed and packaged without extracting a ball-of-mud later. Multi-repo split is deferred until there is a concrete packaging need.
